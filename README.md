# Wave 성장 통계

Wave의 스타 이력으로 여러 미래를 모의하고, **대표 프로젝트·재작성·모듈 도입으로 생태계가 확장되는 조건**을 추가해 비교하는 로컬 도구다.

결과는 한국어 터미널·표·그래프·HTML로 제공한다. 입력 CSV와 결과는 인터넷에 전송하지 않는다. **과거 자료로 추정한 값과 사용자가 넣은 미래 가정은 분리한다.**

## 업데이트와 실행

Python 3.11 이상을 사용한다. 이미 저장소를 받은 상태라면:

```bash
cd statistics
git pull --ff-only
source .venv/bin/activate
python -m pip install -e '.[dev]'
```

처음 설치한다면 `git clone https://github.com/LunaStev/statistics.git` 후 해당 디렉터리에서 `python3 -m venv .venv`를 실행하고 위의 가상환경 활성화·설치를 진행한다.

한글 글꼴은 시스템에 설치된 것을 사용한다. Fedora에서 글꼴이 없다면:

```bash
sudo dnf install google-noto-sans-kr-fonts
```

[해당 Fedora 패키지](https://packages.fedoraproject.org/pkgs/google-noto-sans-cjk-subset-fonts/google-noto-sans-kr-fonts)는 Noto Sans KR을 제공한다. 나눔고딕·맑은 고딕·AppleGothic도 인식한다. 설치 후 새 Python 프로세스에서 실행한다. 글꼴이 없으면 대규모 계산 전에 안내하며 `--no-plots`로 이미지 없이 실행할 수도 있다.

## 이번 생태계 실험

```bash
python wave_growth_forecast.py ~/star-history-2026924.csv \
  --scenario scenarios/ecosystem.example.toml \
  --simulations 1000000 \
  --target 100000 \
  --years 30 \
  --chunk-size 25000 \
  --jobs 6 \
  --output results/1m-ecosystem

xdg-open results/1m-ecosystem/report.html
```

**보고서 첫 화면과 `요약.txt`에 결론부터 나온다.** 같은 가상 미래마다 기존 직접 유입만 있는 경로와 생태계 조건을 추가한 경로를 같이 계산하므로 기준선 파일을 따로 만들어 합칠 필요가 없다.

`--simulations`는 가상 미래 개수, `--target`은 목표 스타 수다. 예측 기간과 목표는 별개다. 생태계 조건을 생략하면 기존 스타 이력 모형만 실행한다. `python -m growth`와 설치 후 `wave-statistics`도 같은 진입점이다.

## 어떤 조건을 넣었나

| 시나리오 파일 | 넣는 조건 |
|---|---|
| `scenarios/single-project.toml` | 대표작 하나가 등장 |
| `scenarios/ecosystem.example.toml` | 대표작·재작성·모듈 도입이 이어짐 |
| `scenarios/strong-feedback.toml` | 사용 전환과 파생 프로젝트 확산을 더 크게 가정 |

이 예시들의 날짜·수치에는 실제 발생 가능성 순위가 없다. **전부 민감도 비교용 가정**이며 2027년의 사건도 예정된 일이 아니다. 10월 5일·12월 5일 등의 언어 출시 계획을 자동으로 성공 사건으로 바꾸지 않는다.

예시 파일을 복사해 `earliest`, `latest`, `leads_per_day`, `star_probability`, `adoption_probability` 등을 바꾼다. 설정 옆에 한국어 설명을 붙였다. `probability=1`은 ‘일어난다고 가정해 계산’이라는 뜻이다. 0이면 해당 사건은 발생하지 않는다. 하나의 경로가 강제로 목표에 도달하게 만드는 코드는 없다.

## 생태계 계산 흐름

```
대표작 / 재작성 / 모듈 도입
  → 신규 발견
     → 스타 표시
     → Wave 사용
        → 새 프로젝트 개발
           → 일부 프로젝트 확산
           → 일부 개발자의 언어 직접 기여
              → 후속 프로젝트 시작률 향상
```

스타와 사용자를 별도로 세고 중복 발견을 제한한다. 개발 기간, 개발 중 포기, 프로젝트 활동 종료, 기여 활동 종료, 사건 영향 감소, 잠재 독자 소진을 포함한다. 큰 프로젝트 하나가 계속 성공하는 경로만 만드는 대신 후속 활동이 사라지는 경로도 허용한다.

직접 유입 기준선은 유지하고 **겹치지 않는 추가 집단의 효과를 더하는 모형**이므로, 비교 결과가 기준선보다 낮아지지는 않는다. 이는 가정의 구조이지 실제 프로젝트가 항상 도움이 된다는 증명이 아니다. 사건이 없고 초기 추가 개발자도 0이면 기준선과 동일한 결과가 나온다.

## 결과에서 읽을 파일

| 파일 | 내용 |
|---|---|
| `report.html` | 한국어 요약·표·그래프 전체 |
| `요약.txt` | 어려운 통계 용어를 줄인 핵심 결과 |
| `기준선과_생태계_비교.csv` | 기존 유입과 생태계 조건의 차이 |
| `중간목표_비교.csv` | 100·250·500·1천·…·10만 스타 비교 |
| `생태계_입력_가정.csv` | 어떤 값을 가정했는지 |
| `생태계_추이.csv` | 추가 스타·발견자·프로젝트·기여자 변화 |
| `추가_유입_유지_시점.csv` | 평균 추가 유입이 하루 1·5·10·30개 이상으로 유지되는 시점 |
| `연도별_스타_예상.csv` | 연도별 중앙값과 중간 80% 범위 |
| `도달_요약.csv` | 전체 중앙 도달일과 도달한 경로만의 중앙 도달일 |
| `과거_검증_요약.csv` | 과거를 가리고 예측해 본 결과 |
| `모형별_비중.csv` | 기존 유입 모형의 검증 비중 |

영문 이름 CSV/JSON은 기존 분석 코드와의 호환성을 위해 유지하는 기계용 원본이다. 사용자용 표는 한국어 이름으로 따로 저장한다. `run.json`과 `chunks/`는 재현·재개를 위한 파일이다.

‘유입 유지 시점’은 **입력한 조건에서 정의한 관찰 기준**이다. 언어의 보편적인 임계점, 미래 폭발의 확정 날짜, 생태계 재생산수가 1을 넘는 날짜를 추정한 것이 아니다. 매일 실제 스타가 정확히 그 수만큼 생긴다는 뜻도 아니다.

## 검증과 재개

큰 실행 전에 과거 예측 시험과 시나리오 설정만 확인:

```bash
python wave_growth_forecast.py ~/star-history-2026924.csv \
  --scenario scenarios/ecosystem.example.toml \
  --validate-only --output results/ecosystem-validation
```

100만 대신 10만 회로 시험하려면 `--simulations 100000`을 지정한다. 메모리를 줄이려면 `--chunk-size 10000 --jobs 2`처럼 작업자 수와 청크 크기를 조절한다. 청크가 너무 작으면 저장 파일이 많아진다.

중단한 실행은 **같은 명령에 `--resume`**을 추가한다. 완료한 청크를 검증하고 재사용한다. 같은 소스·입력·설정·시드·청크 크기에서는 작업자 수만 바꾸어도 결과가 같다. `--no-plots`로 재개한 뒤 나중에 다시 이미지 생성을 요청할 수도 있다.

**v0.2 실행 폴더에는 이어 쓰지 않는다.** 소스·라이브러리·설정·시나리오가 바뀌면 새 출력 폴더를 사용한다. 이전 결과를 자동 삭제하거나 덮어쓰지 않는다.

## 해석과 민감도

단기 예측 비중은 모형이 참일 확률이 아니다. 30년 미도달은 영원히 못 간다는 뜻이 아니다. `도달한 경로만의 중앙일`과 `전체 중앙일`을 혼동하지 않는다. 표본 절반이 기간 안에 도달하지 않으면 전체 중앙일은 기간 내 확인되지 않았다고 표시한다.

계산 횟수를 늘리면 몬테카를로 표본오차가 줄지만 미래 가정의 오차까지 사라지는 것은 아니다. 예시 파일을 더 낙관적으로 고쳤다면 결과가 높아지는 것은 그 조건의 영향이다. 새로운 실측 근거를 얻은 것이 아니다.

생태계의 기본 시간 간격은 최대 7일이다. `--step-days 1`로 더 촘촘하게 계산해 민감도를 확인한다. 1·7일 결과는 서로 다른 난수 사용과 시간 근사를 포함하므로 개별 경로가 같지는 않다.

기준선의 추상적인 스타 비례 효과와 실제 생태계 효과가 겹칠 가능성을 확인하려면 같은 시나리오에 `--model negative_binomial` 또는 `--model long_poisson`을 사용한다. 기본 모형 조합은 `--model ensemble`, 동일 비중은 `--weights equal`이다.

기존 기본 설정 파일 `--config config.example.toml`도 계속 지원한다. CLI 인수가 기본 설정 TOML보다 우선한다. 시나리오 설정은 `--scenario`의 별도 파일이며 검증 점수로 자동 추정하지 않는다. 입력은 일별 누적 비음수 정수 스타다. 누락 날짜·감소·충돌 중복은 명시적인 오류로 처리한다.
