# 생태계 조건부 실험

## 무엇을 계산하나

질문은 **“미래 대표 프로젝트가 언제 반드시 나오는가”가 아니라, “이런 프로젝트와 채택 경로가 생긴다는 조건을 넣으면 기존 예측과 얼마나 달라지는가”**다.

기존의 다섯 스타 유입 모형과 과거 시점별 검증은 그대로 사용한다. 새 생태계 계층은 이 모형의 검증 점수에 끼워 넣지 않는다. 발생 날짜, 전환율, 프로젝트 수명과 잠재 독자 수는 전부 사용자 입력이다. 이를 사후확률이나 데이터로 학습한 외생 충격 확률이라고 부르지 않는다.

## 상태와 흐름

```
대표작 / 재작성 / 모듈 도입
        ↓
아직 Wave를 발견하지 않은 추가 독자
        ├─ 스타 표시
        └─ Wave 사용
             ↓
          개발 시작 → 진행 중 포기 가능
             ↓
          프로젝트 완성
             ├─ 일반적인 파생 프로젝트
             ├─ 확산력이 큰 파생 프로젝트
             └─ 개발자의 언어 직접 기여
                    ↓
             후속 프로젝트 시작률 향상
```

스타를 곧바로 사용자로 바꾸지 않는다. 신규 발견자에 대해 스타 전환과 사용 전환을 별도로 추출한다. 두 결정은 조건부 독립이라고 가정한다. 사용자는 한 번만 새 프로젝트를 시작할 수 있는 집단으로 단순화했다. 기여자는 해당 프로젝트가 끝난 뒤에도 언어에 기여할 수 있으므로 앱 활동과 기여 역할은 중첩될 수 있다. 이 수들을 합쳐 고유 인원 수라고 읽지 않는다.

표의 활동 프로젝트·완성 프로젝트·큰 확산 프로젝트는 **자동 생성된 파생 프로젝트** 수다. 사용자가 설정한 최초 외부 사건은 이 수에 포함하지 않는다. 외부 사건 자체는 입력 가정 표에서 확인한다.

## 외부 사건

사건별로 `[earliest, latest]` 날짜 안에서 정수 날짜를 균등 추출한다. `probability`는 해당 사건을 시나리오에 발생시키는 **입력 조건**이다. 1이면 조건부 발생, 0이면 미발생이다. `log_sigma`가 0이면 강도가 고정되고, 그렇지 않으면 로그정규 강도를 추출한다.

입력 초기 도달 강도 `L`가 로그정규 분포의 평균이 되도록 `log(L) - sigma²/2`를 위치 매개변수로 사용한다. 사건 발생 시점 `T` 이후의 평균 도달 시도는 다음과 같다.

\[
e(t)=L\exp[-h(t-T)],\quad h=\log(2)/H,\quad t\ge T.
\]

도달 시도는 사건이 실제로 존재하는 구간에 대해서만 적분한다. 사건이 구간 마지막 날에 생겼다고 해서 그 구간 전체에 영향을 준 것으로 계산하지 않는다. 재작성·모듈·대표작은 현재 같은 노출 함수 틀을 사용하며 입력 강도·수명·발생 날짜로 차이를 둔다. 카테고리만 바꾼다고 임의의 보너스를 주지 않는다.

`leads_per_day`는 하위 프로젝트 스타 수가 아니다. Wave를 발견할 수 있는 사람에게 도달하려는 시도의 평균이다. 하위 프로젝트의 스타에서 이 값으로 변환하는 실측 관계는 아직 없다.

## 중복 발견과 유한한 집단

`A`는 기존 유입과 겹치지 않는 **추가 잠재 독자 집단**의 크기다. 한 구간의 전체 평균 도달 시도가 `E`, 이미 발견된 인원이 `D`이면 다음 식으로 신규 발견자를 추출한다.

\[
D_{new}\sim\operatorname{Binomial}(A-D,1-e^{-E/A}).
\]

이는 포아송 도달 시도를 집단에 균등 배분한다는 가정에서 나온다. 같은 사람의 반복 노출을 다시 신규 사용자·스타로 세지 않는다. 따라서 이 집단에서 생기는 신규 스타는 최대 `A`개다. `A`는 최종 스타 수 상한을 자료에서 추정한 값이 아니다.

신규 발견자의 별 표시와 사용 여부는 각각 설정한 확률로 이항 추출한다. 전환하지 않은 사람이 나중에 다시 결정을 바꾸는 과정과 스타 취소는 이번 모형에 없다.

## 개발 지연, 활동 종료, 기여 환류

프로젝트 시작은 미착수 활동 개발자에 대한 일별 위험률로 모델링한다. 진행 중 개발은 완료 위험률 `1/development_mean_days`와 포기 위험률 `log(2)/developer_half_life_days`가 경쟁한다. 구간 내 이탈자를 이항으로 뽑고, 완료/포기를 상대 위험률에 따라 나눈다.

완성한 프로젝트 중 일부는 큰 노출을 만드는 상태로 들어간다. 나머지는 일반 프로젝트로 활동한다. 프로젝트 활동과 언어 기여 활동에는 각각 반감기가 있으며 영구적으로 유지된다고 가정하지 않는다.

직접 기여자 `C`가 프로젝트 시작률을 돕는 효과는 다음 배수로 제한된다.

\[
B(C)=1+b_{max}\frac{C}{C+c}.
\]

이 계수는 컴파일러 품질을 측정해 추정한 인과효과가 아니다. 사용자가 선택한 대리 가정이다. `contribution_max_boost=0`으로 끄고 결과를 비교할 수 있다. 새로 생긴 프로젝트·기여·사용자의 효과는 다음 구간부터 적용해 한 구간에서 무한히 재귀 증폭하지 않도록 한다.

## 기존 기준선과의 비교

기존 모형의 난수 스트림은 생태계 계층과 분리되어 있다. 각 경로에서 기준선 `S_base`와 추가 스타 `S_extra`를 따로 계산한다.

\[
S_{scenario}(t)=\min(S_{base}(t)+S_{extra}(t), target).
\]

생태계 스타를 기준선의 `birth` 모형에 다시 넣어 이중으로 증폭하지 않는다. 비교는 같은 직접 유입 경로에 대한 쌍별 비교다. 그래서 시나리오 차이가 난수로 달라진 기준선 때문에 만들어지지 않는다.

**이 비교는 기존 유입이 유지되고 추가 집단이 서로 겹치지 않는다는 가정이다. 따라서 시나리오 스타가 기준선보다 낮아지지 않는 구조다.** 관심의 잠식, 기존 유입 감소, 부정적 사건은 별도로 모델링하지 않았다. 관측된 기존 성장 자체가 이미 잠재 생태계 효과를 포함할 수 있으므로 `--model negative_binomial` 또는 `--model long_poisson`으로 기준선을 바꾸는 민감도 비교도 필요하다.

## ‘임계점’ 대신 표시하는 구체적 지표

생태계의 **평균 추가 유입률**이 하루 1·5·10·30 스타 이상으로 설정한 일수 동안 유지되는 첫 시점을 기록한다. `sustained_days`의 기본값은 30일이다. 이 값은 언어의 보편적인 성장 임계점이나 피드백 재생산수 `R=1`을 추정한 결과가 아니다. 이름을 그렇게 붙이지 않는다.

평균 유입률에 대한 격자 판정이므로 매일 실제로 정확히 그 수 이상의 스타가 생겼다는 뜻도 아니다. 연속한 구간의 평균값이 기준을 충족해야 유지 일수를 쌓는다. 기준을 처음 넘은 경계 구간은 보수적으로 제외한다. 기간 내 미충족 경로를 버리지 않고 확률 분모에 포함한다.

## 계산과 검증

기존 모형은 자신의 정확한 구간 전이분포를 이용한다. 생태계는 집단 상태를 구간 끝에 갱신하는 이산 근사다. 기본 간격은 최대 7일이고 `--step-days 1`로 바꿔 시간 해상도 민감도를 비교한다. 이벤트의 지수 노출 적분은 구간 안의 등장 시점을 반영한다. 생성 프로젝트의 구간 노출은 시작 시점 상태와 기대 생존시간을 사용한다.

전체 시뮬레이션 × 모든 날짜 행렬을 저장하지 않는다. 경로별로 연도별 값·목표 통과 구간·활동 통계를 저장하고 일부 경로만 그래프로 보관한다. 청크별 고정 스트림을 사용해 작업자 수와 완료 순서에 영향받지 않는다. 단, 청크 크기를 바꾸면 스트림 구성이 달라진다.

기존 `summary.csv` 등 기계용 스키마는 유지한다. 한국어 이름 CSV, `요약.txt`, `report.html`, 그래프가 사용자용 출력이다. 생태계 조건부 결과에는 기존 기준선 해석식 확률을 그대로 붙이지 않고 해당 칸을 비워 둔다. 조건부 도달 중앙값, 전체 경로 중앙값, 기간 내 미도달을 분리한다.

테스트에는 무효 설정, 사건 없음, 사건 강도 적분, 전환 지연, 잠재 집단 소진, 기여 환류, 단발성 급증, 지속 기준, 기준선 난수 보존, 목표 상한, 병렬 재현성, 재개 설정 불일치, 한국어 보고서가 포함된다. 사용자 데이터의 백만 회 실행은 테스트에 넣지 않는다.
